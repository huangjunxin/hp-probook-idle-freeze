## 三、故障现象（可复述）

1. **发生时机**：机器处于**空闲**状态时最易发生——不运行大型程序、CPU 占用接近 0、整机功耗约 4 W 的情况下，几分钟到数十分钟内突然冻死。运行高负载任务时反而稳定。
2. **表现**：画面完全静止，鼠标键盘无响应，`Caps Lock` 指示灯不变化，无蓝屏、无报错、无自动重启。等待数十分钟不恢复。
3. **唯一恢复方式**：长按电源键强制断电后重新开机。
4. **与电源状态无关**：无论插电源还是用电池、无论屏幕亮着还是已关闭、无论是否处于连接待机，均会发生。
5. **偶发伴随现象**：重启后偶有极短暂的黑屏/闪屏；极少数情况下重启后提示 DMA Protection 相关告警。

## 五、关键证据

### 5.1 全部 18 次均为「无蓝屏硬断电」

- `Kernel-Power 41` 的 `BugcheckCode` 字段全部为 `0`；
- `C:\Windows\Minidump` 目录**无任何转储文件**；
- `LongPowerButtonPressDetected` 字段全部为 `false`。

系统在被截断前来不及记录任何崩溃信息，符合「整机瞬时失去响应 / 供电或时钟被切断」的特征，而非普通软件崩溃。

### 5.2 故障与电源状态无关（关键）

第 17 次（记录于 2026-10-28 09:33）的 `ConnectedStandbyInProgress` 为 **`false`**。

对应 2026-10-27 的 Sleep Study 记录显示：

| 项目 | 实测值 |
|---|---|
| 当日场景会话 | 仅 1 个 Active 会话，09:30:56 起持续约 6 小时 |
| 当日息屏（Screen Off）会话数 | **0 次** |
| 功耗快照区间 | 25 个，**全部 `MonitorOn = True`** |
| 11:01 之后的 SoC 封装功耗 | 稳定在 **3.9 – 4.0 W**（CPU 约 0.7 W） |
| 冻死前状态 | 屏幕亮着、系统空闲、无任何高负载任务 |

即：**屏幕全程亮着、未进入任何待机状态、功耗仅 4 W 的情况下整机冻死。** 因此本故障不能归因于「睡眠唤醒失败」，而是发生在**空闲电源状态转换过程**中。

### 5.5 固件已写入错误记录，但记录内容无效

`WHEA-Logger` 累计 18 条事件（16 条为 CPER 错误记录）。最近 15 天内 8 条，其中 **7 条 `ErrorSeverity = Fatal`**，错误段类型 **100% 为 `Firmware Error Record Reference`**（GUID `81212A96-09ED-4996-9471-8D729C8E69ED`），未出现处理器、内存、PCIe 等硬件错误段。

**但需要如实说明**：这些记录的载荷本身是无效数据——

- 单条记录 13,736 字节中，`0xDEADBEEF`（未初始化内存填充值）出现 **1,243 次，约占 36% 字节**；
- 记录中的引用 GUID 全为零；
- 头部时间戳解析结果为公元 **4591 年**，而该字段的验证位却声明其有效。

即：**固件在写入错误记录时读到了未初始化的内存区域**。本项证据只能说明「故障发生时固件确实被触发并尝试记录」，**不足以指认具体硬件组件**，特此说明，避免误读。

### 5.6 Sleep Study 显示系统从未真正进入低功耗

2026-10-20 ~ 10-27 期间的 Sleep Study 报告：

| 项目 | 实测值 |
|---|---|
| `Sleep` / `Standby` 场景会话 | **0 次**（7 天内无一次真正进入低功耗待机） |
| 息屏会话中的 `PDC Phases / No CS Phase` 阻挡 | 18 次会话 **全部命中**，有效时间占比 **99%** |
| 息屏期间的 SoC 封装功耗 | **3.7 – 17.4 W**（正常 Modern Standby 应低于 0.5 W） |
| 唤醒侧 `MSExitPerformance.TotalInMs` | **65,535 ms**（计数器封顶值） |

说明本机的空闲电源状态转换链路工作不正常：关闭屏幕后平台始终未能进入连接待机阶段。

### 5.7 处理器空闲态由 PEP 插件管理（与故障栈对应）

系统日志中每次开机都会记录各处理器暴露的电源管理能力（`Microsoft-Windows-Kernel-Processor-Power`，ID=55）：

```
Processor N in group 0 exposes the following power management capabilities:
  Idle state type: Micro Power Engine Plugin (11 state(s))
  Performance state type: ACPI Collaborative Processor Performance Control
```

即：**本机 CPU 的 11 个空闲状态全部由 PEP（Platform Extension Plugin）微电源引擎统一管理**，而非传统 ACPI C-state 直控。

这一点与本故障高度相关：整机冻死发生在「CPU 请求进入空闲态」的时刻，而该路径必然经过 PEP 的空闲状态转换（`PepIdleExecute → PpmIdleExecuteTransition → PoIdle → KiIdleLoop`）。同时，电源状态转换过程中平台会联动调整 PCIe 链路电源状态，两者耦合在同一时点。

> 本次记录为信息级事件，非告警，仅用于说明空闲态管理与故障发生时点重合。

## 六、技术判断（供参考，非结论）

综合上述证据，本机故障表现为**空闲电源状态转换过程中的整机死锁**，可能处于以下层面：

1. **平台空闲转换（idle-state transition）本身**：CPU 进入深层空闲时，平台在同一个时点联动调整 PCIe 链路等多项电源状态，唤醒路径无法恢复，导致整机死锁。**需要说明的是：其中「PCIe 链路降档（ASPM）」这一项已在本机被实测排除**（见第七节），因此问题更可能出在转换逻辑本身，或其它与空闲态联动的电源域上；
2. **固件层面**：`WHEA` 记录的 `Firmware Error Record` 表明固件在故障发生时被触发，但记录内容为未初始化数据，无法进一步定位；
3. **虚拟化层参与**：本机基于虚拟化的安全（VBS / 内存完整性）处于运行状态，`powercfg /a` 明确提示「混合睡眠……虚拟机监控程序不支持此待机状态」，说明虚拟机监控程序确实介入了电源状态切换流程。

**需要强调**：本判断基于应用层可见的日志与报告，**不等于已定位到具体缺陷模块**。最终判定需依赖贵方的固件调试能力与硬件诊断结果。

**参考信息**：HP 官方支持社区存在同型号（ProBook 4 G1i 14）同类故障讨论帖 —— *"Second Probook 4 G1i 14 causes random freezes and reboot"*，其中用户报告两台同 part number 设备复现「空闲必冻、高负载稳定」，内核栈指向 `intelppm!HvRequestIdle → PepIdleExecute → PpmIdleExecuteTransition → PoIdle → KiIdleLoop`；该帖中对该用户有效的缓解措施为将「PCIe → 链接状态电源管理」设为「关闭」。

**但本机已实测该措施无效，具体情况如下**：2026-10-28 10:08 将「PCIe → 链接状态电源管理」的接通电源与使用电池两项均设为「关闭」，并通过 `powercfg /query` 回读确认为 `0x00000000 / 0x00000000`（设置确认生效，且电源方案未变更、设置未被打回）；**当日下午 14:12 再次冻死，距设置生效 4 小时 4 分钟**。故本故障不能简单归因于 PCIe 链路电源管理，该帖的缓解方案在本机不适用。

## 附录：现场复核命令（供工程师验证）

```powershell
# 1) 异常断电全量清单（重点看 ConnectedStandbyInProgress 与 BugcheckCode）
Get-WinEvent -FilterHashtable @{LogName='System'; Id=41} -MaxEvents 60 |
  Sort-Object TimeCreated | ForEach-Object {
    $d=@{}; ([xml]$_.ToXml()).Event.EventData.Data | ForEach-Object { $d[$_.Name]=$_.'#text' }
    [pscustomobject]@{
      记录时刻=$_.TimeCreated
      连接待机中=$d['ConnectedStandbyInProgress']
      BugcheckCode=$d['BugcheckCode']
      长按电源键=$d['LongPowerButtonPressDetected']
      固件启动错误数=$d['WHEABootErrorCount']
    }
  } | Format-Table -AutoSize

# 2) 固件错误记录数量与严重性
Get-WinEvent -FilterHashtable @{LogName='System'; ProviderName='Microsoft-Windows-WHEA-Logger'} |
  Group-Object Id | Select-Object @{n='事件ID';e={$_.Name}}, Count

# 3) BIOS 版本变更史
Get-WinEvent -LogName 'HP SFU Service' |
  Where-Object { $_.Message -match 'BIOS' } |
  Sort-Object TimeCreated | Select-Object TimeCreated, Message

# 4) 当前 PCIe 链接状态电源管理档位（0=关闭 1=中等 2=最大电源节省量）
powercfg /query SCHEME_CURRENT SUB_PCIEXPRESS ee12f906-d277-404b-b6da-e5fa1a576df5

# 5) 生成睡眠研究报告
powercfg /sleepstudy
```
